# 考前準備

## 1. 確認考試資訊

從課程 README 和學期 README 的考試表讀，缺的問學生或去平台公告查：
- 日期、時間、地點
- 範圍（第幾章到第幾章、含不含最後一週）
- 形式：筆試／上機／報告；開書或關書；可帶幾張小抄；**能不能用電腦或 AI**
- 上機考：考場電腦有什麼工具（例：學校電腦可能只有 NetBeans 沒有 IntelliJ），提醒學生先去考場練一次

新資訊寫回課程 README 與學期 README。

## 2. 找弱點

- 讀這門課每份 `作業/*/引導紀錄.md` 的「卡住的地方」「下次要複習」
- 用解答模式完成的作業（截止日表備註有寫）列為「需要自己再練一次」：考前請學生不看解答重寫一遍
- 問學生自評每章的熟悉度（1–5）
- 出 5–10 題的診斷小考（每章 1–2 題），用結果排優先順序

## 3. 排計畫

依「離考試天數 × 弱點 × 比重」排每日計畫，同一天有多科就穿插。原則：
- **主動回想**優先於重讀：每天先不看筆記寫出昨天的重點，再對答案
- **間隔重複**：弱點在第 1、3、7 天各複習一次
- **程式課要動手寫**：每天默寫骨架、寫一題，不只是看
- 考前一天只做小抄與錯題，不學新東西

計畫做成 PDF（`<學期>/考試複習/原始檔/` → `/make-note` 的轉檔流程），學生手機上看。

## 4. 練習

- 一次出一題，等學生回答再給回饋，不要一次丟整份答案
- 答錯時用 `/homework` 引導模式的提示階梯，引導學生自己找到錯
- 模擬題用講義與作業的題型自己改編，不要假裝是考古題
- 能帶小抄的考試，最後幫學生把「自己常錯的」整理進小抄

## 5. 考後

考卷發回來後，可以用解答模式做訂正：每題錯在哪、正確思路、一題類似題。錯的題目加進課程 README 的「易錯點」。
