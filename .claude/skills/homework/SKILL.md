# 寫作業：引導模式與解答模式

兩種模式並存，**由學生決定**。Claude 的工作是從學生這次的說法判斷他要哪一種，判斷不出來就問。

## 0. 判斷模式

| 學生的說法 | 模式 |
|---|---|
| 「陪我寫」「教我」「我卡住了」「給我提示」「幫我看我寫的哪裡錯」「這題怎麼想」 | **引導模式** |
| 「幫我寫」「幫我做完」「給我答案」「完整解答」「我要訂正」「考完了想看正解」 | **解答模式** |
| 「處理一下 HW3」「有沒有沒交的作業」（沒說要怎麼做） | **先問一句**：「這份要我陪你寫（引導），還是直接做完給你（解答）？」 |

- 不要自己猜，也不要把學生沒說的偏好當成預設。
- 同一份作業中途可以切換（例如前兩題引導、最後一題直接給解答）。學生說了就照做。
- 學生如果在 `CLAUDE.local.md` 寫了「說法模糊時偏好」，模糊時照那個做，不用問。

## 1. 開始前（兩種模式都做）

1. 讀課程 README 的「AI 使用規定」和「作業繳交規定」。
   - 老師禁止 AI 代寫、而學生選了解答模式：**提醒一次**老師的規定（引用原話與出處），之後照學生的決定做，不重複說教。
2. 確認截止時間與繳交格式（檔名規則、檔案類型、是否分組）。
3. 建好 `作業/<作業名>/`，放題目與附件。

## 2. 引導模式

目標是**學生交出去的東西是自己寫的，而且寫完真的會**。

先建空白骨架檔（只有檔名、class 名、老師給的部分）。學生卡住時，從最低階開始給，**試過還是不行才往上一階**：

| 階 | 給什麼 | 例（寫一個算平均的方法） |
|:-:|---|---|
| 1 | 請學生用自己的話說題目：輸入是什麼、輸出是什麼 | 「這個方法收到什麼？要回傳什麼？」 |
| 2 | 指出相關的觀念與講義頁數 | 「這題會用到陣列走訪，講義 p.12 的 for 迴圈」 |
| 3 | 一起拆步驟（中文虛擬碼） | 「1. 加總 2. 除以個數 3. 回傳」 |
| 4 | 給骨架或一行關鍵語法，其餘留空 | `for (int i = 0; i < ____; i++)` |
| 5 | 指出學生程式**哪一行**錯、錯在哪、為什麼 | 「第 7 行整數相除會捨去小數」 |

- 不一次給完整程式；不直接改學生的檔案，說明要改哪裡，讓學生自己改。
- 不只說「錯了」：說為什麼錯，並請學生預測改了之後的結果。

**檢查學生的成品**：
- 程式：實際編譯、執行，用題目測資和邊界值（0、負數、空字串、跨日、最大值）測，把真實輸出給學生看。
- 文字作業：對照題目要求逐項檢查（字數、格式、有沒有回答到問題），指出哪裡不夠。
- 計算題：請學生寫出過程，找出第一個出錯的步驟。

**留下引導紀錄** `作業/<作業名>/引導紀錄.md`（`/exam-prep` 會讀它找弱點）：

```markdown
# HW2 引導紀錄
- 日期：
- 卡住的地方：
- 用到第幾階提示：
- 自己寫出來的部分／靠提示寫出來的部分：
- 下次要複習：
```

## 3. 解答模式

把整份作業做完，成品放在 `作業/<作業名>/`，**檔名照課程規定**。每份附一段「做法與為什麼」（寫在 `說明.md` 或成品開頭），目標是學生看得懂、被老師或助教問到答得出來：

- 思路：這題在考什麼觀念，為什麼這樣做
- 逐步講解：關鍵的每一步、每一段程式在做什麼
- 常見錯誤：這題最容易錯在哪
- 一題類似的練習題（學生想練時可以自己寫）

規則：
- 程式一律實際編譯執行，附真實輸出；計算題附完整過程。
- 需要學生本人資料才做得了的（個人心得、照片、分組成員、要登入其他服務），先做完能做的部分，缺的地方清楚標註。
- 心得、反思類作業：可以給架構和寫法建議，但內容要學生自己的經驗；Claude 寫的段落要標明是草稿，提醒學生改成自己的話。
- 在學期 README 截止日表的備註寫「解答模式」，`/exam-prep` 會把它列為「需要自己再練一次」。

## 4. 繳交（兩種模式都一樣）

繳交由學生自己做。可以幫忙檢查檔名、檔案格式、有沒有漏題；要代為上傳，必須學生每次明確同意。
